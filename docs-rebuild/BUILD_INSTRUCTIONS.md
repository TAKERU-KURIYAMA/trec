# Message ドキュメントサイト構築指示書

## 🎯 構築方針

**ミニマムスタートから段階的に機能を追加していく手作りアプローチ**

### 基本理念
- **段階的構築**: 最小限の機能から開始し、徐々に拡張
- **手作り重視**: 自動生成ではなく、手動で丁寧に作成
- **実用性優先**: 見た目より内容と使いやすさを重視
- **継続可能性**: メンテナンスしやすい構造

## 📋 全体構築計画

### Phase 1: 基盤構築 (1-2日)
**目標**: 最小限のVitePressサイトを動作させる

#### 成果物
- 動作するVitePressサイト
- 基本的なホームページ
- シンプルなナビゲーション
- 1つのサンプルページ

#### 完了条件
- `npm run docs:dev` が正常に動作
- ブラウザでサイトが表示される
- ページ間のナビゲーションが機能

### Phase 2: コンテンツ基盤 (2-3日)
**目標**: 主要ページの骨格を作成

#### 成果物
- 機能一覧ページ（基本版）
- API仕様ページ（基本版）
- システム設計ページ（基本版）
- 基本的なサイドバーナビゲーション

#### 完了条件
- 全主要ページにアクセス可能
- ページ構造が論理的
- 基本的な情報が記載されている

### Phase 3: スタイリング (1-2日)
**目標**: 読みやすいデザインを適用

#### 成果物
- カスタムCSS
- ブランドカラーの適用
- レスポンシブ対応
- 読みやすいタイポグラフィ

#### 完了条件
- モバイルで適切に表示
- Messageブランドカラーが適用
- 読みやすいフォントサイズ・行間

### Phase 4: 高度機能 (2-3日)
**目標**: 便利な機能を追加

#### 成果物
- 検索機能
- Mermaid図表サポート
- コードハイライト
- 内部リンクの最適化

#### 完了条件
- サイト内検索が動作
- 図表が正しく表示
- コードが見やすくハイライトされる

### Phase 5: 最適化・デプロイ (1日)
**目標**: 本番環境での運用準備

#### 成果物
- GitHub Actionsワークフロー
- パフォーマンス最適化
- SEO対応
- 運用ドキュメント

#### 完了条件
- 自動デプロイが動作
- ページ読み込みが高速
- 検索エンジンでインデックス可能

## 🔧 開発フロー

### 日次作業フロー
1. **朝**: 当日のタスクを確認・優先順位付け
2. **作業**: 1つのタスクに集中して完了
3. **テスト**: ローカルでの動作確認
4. **夕方**: 進捗確認・翌日のタスク準備

### 品質チェック項目
- [ ] ローカルで正常に表示される
- [ ] リンクが正しく動作する
- [ ] モバイルで適切に表示される
- [ ] 誤字・脱字がない
- [ ] マークダウン記法が正しい

### トラブルシューティング手順
1. **エラー発生時**: エラーメッセージを詳細に確認
2. **動作不良時**: ブラウザのDevToolsでデバッグ
3. **解決困難時**: 最小限の構成に戻して原因特定

## 📊 進捗管理

### 完了基準の定義
- **Task完了**: 機能が正常に動作し、テストに合格
- **Phase完了**: 全Taskが完了し、成果物が確認できる
- **Project完了**: 全Phaseが完了し、本番環境で動作確認

### 品質基準
- **機能性**: 想定通りに動作する
- **使いやすさ**: 直感的にナビゲーションできる
- **保守性**: 後から修正・拡張しやすい
- **パフォーマンス**: 適切な読み込み速度

- **ページ数**: 最低15ページ
